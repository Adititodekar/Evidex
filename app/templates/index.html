RERS: Routed Evidence-Set Retrieval Architecture

EVIDEX replaces one-shot vector top-k retrieval with a hierarchical, deterministic routing architecture designed specifically to eliminate temporal cross-contamination and the chunk-size dilemma in financial analysis.

[ Ingestion: POST /index ]
PDF Documents (Zip Archive)
   ├── 1. Page-Aligned Extraction (1-based index, table markdown formatting)
   ├── 2. Scanned OCR Fallback (RapidOCR / ONNX Runtime disk cache)
   ├── 3. Section Tree Parser (TOC bookmarks + structural heading regex)
   ├── 4. Paragraph-Aware Chunker (60–250 words, strict page boundary invariant)
   ├── 5. Dynamic Metadata Layer (Doc Cards, Sibling Discrimination Table)
   └── 6. Multi-Vector (FAISS FlatIP) & BM25Okapi Indices in data/<collection>/

[ Inference: POST /query ]
User Query
   ├── Step 1: query_understanding (Facet decomposition, temporal resolution, breadth budget)
   ├── Step 2: metadata_filter (Hard filter on Doc Cards + Sibling Discrimination)
   ├── Step 3: doc_router (LLM navigates compact section summaries per facet)
   ├── Step 4: recursive_drilldown (Leaf-section whole selection guarantees complete recall)
   ├── Step 5: coverage_check (Deterministic evidence bounds & adaptive widening)
   ├── Step 6: evidence_verification (Strict relevance classification, budget-capped)
   ├── Step 7: context_assembly (Ordered by Doc/Page, [Doc p.X] tags)
   ├── Step 8: llm_answer_generation (Executive bottom-line, structured sections, comparison tables)
   └── Step 9: claim_check (Sentence-level fact verification against cited chunks)
   └── Output Contract: {answer, chunks, trace, usage} + Langfuse Observability
